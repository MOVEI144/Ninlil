物理的な抜き差しはユーザーが行い、hostは2つのUSB identityの消失・再出現と
serialの再接続を記録する。

Sourceとfirmwareは[前回の保存試験](M1_DURABLE_CAMPAIGN_2026-09-07.md)で検証済みの
`80ab9acd444b577fc687bf6dbcddbf7e13ec2fa3`、recovery-a-init / recovery-b-respを使う。
前回のsnapshotを保持し、今回も両journalの読出しとdevice MD5照合を行ってから、
試験journalのみをcleanした。同じ試験用imageとcampaign設定`2026090703`を再使用するが、
今回の独立した実行labelは`usb-both-01`、新規採番されたメッセージIDで区別する。
再接続の前後ではjournalもメッセージIDも変更しない。

Board A：node 1 / `E0:72:A1:F7:FF:0C`（開始時COM3）。

## 実行手順

1. 個体、元backup、Flash layout、設定、firmware hashを照合して書込みverify。
2. Bをloaderに保持したままAを起動し、1件のローカルcommitとTX_DONEを記録する。
3. ユーザーが2台ともUSBを抜く。hostは両identityが2秒以上同時に存在しないことを記録。
4. ユーザーが2台を再接続。hostは固定COM番号ではなく同じserial / VID / PIDを探し、
   DTR/RTSを無効としてmonitorを開く。再接続後、配送完了まではesptool resetを行わない。
5. 両側のログと100件の完了markerを回収した後、MCUをloaderへ戻してFlashを読出す。
   物理再接続直後の早期bootログが欠けた場合は欠けた範囲を明示する。
6. 最初の未完了ID、両側のcommit済みpayload/ID、相手保存の証拠を照合する。
   summaryだけでは成功としない。必要に応じ、別labelの制御されたreplay試験も行う。

最初のMonitorは全体580秒、各raw log最大2 MiBで打切る。打切り・追加の切断・firmware errorは
受入成功にせず、存在する接続をloaderへ戻して停止する。
保存先は`C:/dev/job/iot/Ninlil/.verify-m1-evidence/usb-*`。

## 書込み途中の電源断との区別

正本[受入手順](M1_HIL_ACCEPTANCE.md)第7段階は、制御された電源断fixtureを必要とする。
手でUSBを抜いた事実から、Flash書込み中に電源が切れたと推定しない。

現在のFlash実装は次の順序で保存する。

| 操作 | Source上の境界 | 必要な観測 |
|---|---|---|
| Header program | `ninlil_flash_store_append_ref`の最初の24-byte write | 書込み区間と実給電の断点 |
| Payload / trailer program | 同関数の2回目のwrite | 区間内の断点と不完全recordの扱い |
| Commit marker | readback照合後の8-byte write | marker・補数の途中切断と再起動判定 |
| Erase | `ninlil_flash_store_format`のerase callback | erase中の断点と残存状態 |
| 配送上の各commit | OUT_ATTEMPT / IN_ACCEPT / receipt handoff / remote evidence | record種別・ID・断点の対応 |

実行には、外部triggerで給電を切れるスイッチ、供給が実際に落ちたことを確認する方法、
書込み区間とcutの時刻を対応付ける記録が必要。USBや測定線から別経路で給電されていない
構成も確定する。ユーザーから制御用スイッチ等は「ない」と回答があり、設備の用意が残る。
制御pinや配線は仮定しない。
これは次の実機手順の準備であり、電源断matrixの成功証拠ではない。
